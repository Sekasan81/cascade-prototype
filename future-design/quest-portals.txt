# Идея: специализированные порталы для заданий

СТАТУС: рабочая концепция будущей версии. Не внедрено в игру. Механика может изменяться и дополняться по мере дальнейшей разработки.

## Основная схема

При генерации задания ему назначается набор условий, по которым определяется, каких пассажиров необходимо отправить.

После принятия задания на станции появляется отдельный портал, связанный именно с этим заданием.

Портал получает условия задания и имеет жёсткую автоматическую фильтрацию: он пропускает только пассажиров, которые соответствуют всем необходимым требованиям.

Таким образом, игрок физически не может отправить через квестовый портал пассажира, который не подходит под условия задания.

## Пример

Задание:

> 🪐 Марс требует 5 инсектоидов для работы в горнодобывающей колонии.

При генерации задания могут быть заданы условия:

- 🐜 раса: Инсектоиды;
- ⛏️ профессия: Шахтёр;
- 👷 статус: Рабочий;
- 🔢 количество: 5.

После принятия появляется:

> 🌀 Марс — Горнодобывающая колония

Портал проверяет характеристики каждого отправляемого пассажира.

Подходящий пассажир:

> 🐜 Инсектоид + ⛏️ Шахтёр + 👷 Рабочий → ✅ пропускается.

Неподходящий пассажир:

> 🐜 Инсектоид + 💼 Торговец + 👷 Рабочий → ❌ не пропускается.

Другой пример:

> 💎 Инсектоид + ⛏️ Шахтёр + 👑 VIP → ❌ не пропускается, если статус/другие условия задания не соответствуют.

## Почему это важно

Пассажир не обязан иметь фиксированное «направление», которое определяет, куда его можно отправить.

Направление назначения фактически задаётся порталом, а ограничения определяются конкретным заданием.

Это позволяет избежать нелогичных ситуаций, когда подходящий по расе VIP-пассажир автоматически становится подходящим кандидатом для рабочего задания.

Например, если Марсу нужны инсектоиды-шахтёры, наличие инсектоида само по себе недостаточно — портал пропустит только пассажира, соответствующего полному набору требований.

## Возможные условия портала

На первом этапе предполагается использовать:

- расу;
- профессию;
- статус пассажира.

В дальнейшем список условий можно расширять, например:

- размер;
- состоятельность;
- черты;
- дополнительные особенности;
- багаж;
- другие характеристики пассажира.

## Завершение задания

Игрок пропускает подходящих пассажиров через соответствующий портал.

Каждый успешно отправленный пассажир увеличивает прогресс задания.

После отправки необходимого количества пассажиров задание выполняется и портал может быть закрыт/удалён.

## Возможная схема

**Генерация задания → условия задания → принятие задания → появление специализированного портала → проверка пассажира → пропуск только при полном соответствии → прогресс задания → выполнение → закрытие портала.**

## Несколько активных заданий

На станции потенциально может одновременно существовать несколько квестовых порталов с разными требованиями.

Например:

- 🌀 Марс — шахтёры;
- 🌀 Венера — туристы;
- 🌀 Альфа — дипломаты.

Один и тот же пассажир теоретически может подходить нескольким порталам, если соответствует их условиям. Конкретное правило такого случая пока не определено.

## Пока не определено

Пока остаются открытыми:

- точный набор условий;
- правила генерации условий;
- может ли пассажир подходить нескольким активным заданиям;
- максимальное количество одновременно активных порталов;
- внешний вид и расположение порталов;
- UI требований портала;
- что происходит с пассажирами, которые не подходят ни под один активный портал;
- дополнительные правила после выполнения задания.

Эта концепция является рабочей основой и может пересматриваться в процессе дальнейшей разработки.
