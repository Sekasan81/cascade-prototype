# Обслуживание пассажиров

СТАТУС: проектирование, не внедрено в игру.

## 1. Принятие пассажира

- Пассажиры появляются в очереди.
- Игрок открывает карточку пассажира кликом.
- В карточке отображаются его характеристики и требования.
- Все комнаты универсальны и автоматически адаптируют условия под заселяемого пассажира.
- Комната имеет качество от 0 до 5 звёзд. Минимальное качество для конкретного пассажира будет определено отдельно.
- При заселении в комнате сразу списывается 1 единица соответствующего ресурса жизнеобеспечения; этим начинается первый цикл поддержки пассажира.
- После помещения пассажира в комнату он считается принятым на станцию.
- После принятия пассажир больше не возвращается в очередь.
- Качество занятой комнаты и правила его улучшения будут определены отдельно.
- После отправки пассажира комната сразу считается свободной. Дополнительная уборка, ремонт или ожидание не нужны.

## 2. Ожидание в комнате

После принятия пассажир может оставаться в комнате сколько угодно долго.

Если у него уже есть подходящий варп — он может быть назначен на него сразу.

Если подходящего варпа нет, пассажир остаётся в комнате до появления возможности отправки.

Пассажир продолжает потреблять ресурс, пока находится в комнате.

Игрок сознательно принимает риск, если берёт пассажира при отсутствии свободного подходящего варпа.

## 3. Потребление ресурса

На текущем этапе баланс максимально простой:
- один пассажир использует один из четырёх типов ресурса жизнеобеспечения;
- при заселении списывается 1 единица ресурса, чтобы запустить первый цикл;
- на границе каждого завершённого цикла списывается ещё 1 единица и сразу начинается следующий цикл;
- расход всегда равен 1 единице за цикл; размер и другие характеристики пассажира могут изменять длительность цикла, но не количество ресурса за цикл;
- длительность задаётся как время цикла в секундах. Модификатор должен явно увеличивать или уменьшать длительность (`+N`/`−N` секунд), чтобы не путать длительность со скоростью.

Ресурс использует система жизнеобеспечения комнаты; пассажир не потребляет еду.

### Нормальный цикл

Пассажир заселён, первая единица ресурса списана, и комната поддерживает для него необходимые условия.

Пока следующий ресурс доступен:
- цикл отображается зелёным;
- пассажир остаётся довольным;
- по окончании цикла он получает следующий ресурс и начинается новый цикл.

### Красный цикл

Если следующий ресурс отсутствует, начинается красный цикл предупреждения.

- Таймер красного цикла не сбрасывается при появлении ресурса.
- Он продолжает идти до конца текущего цикла.
- Если ресурс появляется до окончания цикла, шкала снова становится зелёной.
- Цикл завершается нормально, если ресурс есть в момент его завершения.

Таким образом, у пассажира есть один полный цикл запаса перед получением статуса «Недоволен».

Если красный цикл закончился, а ресурса нет:
- пассажир получает постоянный флаг «Недоволен»;
- дальнейшее восстановление ресурса уже не возвращает 100% награды.

## 4. Состояние «Недоволен»

После получения флага «Недоволен» у пассажира появляется визуальный индикатор — красный злой смайлик.

При наведении на индикатор должна отображаться подсказка:
- причина: ресурс отсутствовал до окончания допустимого цикла;
- последствие: максимальная награда за пассажира снижена до 50%;
- если ресурс не восстановлен до отправки, награда составляет 0%.

После получения флага пассажир:
- продолжает занимать комнату;
- продолжает потреблять ресурс, когда ресурс доступен;
- может быть отправлен обычным варпом;
- не блокирует запуск варпа из-за недовольства.

## 5. Награда

Награда начисляется при отправке пассажира.

На текущем этапе используются:
- кредиты;

Перевозка обычного пассажира даёт кредитную награду, но **не даёт репутацию**. Репутация выдаётся за выполнение квестов согласно `quests.txt`.

Состояния:
- пассажир ни разу не получил флаг «Недоволен» -> 100% награды;
- пассажир получил флаг, но ресурс был восстановлен -> 50% награды;
- пассажир получил флаг и ресурс так и не был восстановлен до отправки -> 0% награды.

Недогруженность варпа не изменяет награду.

Если пассажир становится недоволен непосредственно перед отправкой, система не делает исключений: итог зависит от фактического состояния на момент отправки.

## 6. Направление пассажира

Есть два типа пассажиров.

### Пассажир с конкретной точкой назначения
- сам пассажир сообщает требуемое направление;
- игрок не может изменить это направление;
- пассажир может быть отправлен только через варп с этим направлением.

### Пассажир без конкретной точки назначения
Например, странник.

- направление изначально не задано;
- игрок может выбрать любой подходящий открытый пункт назначения;
- направление можно изменить до момента фиксации пассажира в запущенном варпе;
- если направление ещё не выбрано, пассажир может просто ждать в комнате.

## 7. Работа карточки пассажира

Базовая схема UI сохраняется из текущего прототипа:
1. игрок кликает по пассажиру;
2. открывается карточка;
3. отображаются характеристики и требования;
4. игрок выбирает комнату;
5. при необходимости выбирает направление;
6. при необходимости назначает варп;
7. после действия окно закрывается.

Детальный интерфейс будет дорабатываться отдельно.

## 8. Пауза

Пауза относится ко всей игре без исключений.

Во время паузы:
- пассажир не потребляет ресурс;
- зелёный/красный таймер не идёт;
- состояние пассажира не меняется;
- подготовка варпа не идёт.

## 9. Балансные значения

Предварительные значения для первого тестирования:
- длительности циклов по расам уже предварительно указаны в `passenger-races.txt`; модификаторы длительности ещё предстоит определить;
- один цикл = 1 единица ресурса;
- подготовка варпа: около 60 секунд на 1x.

Эти значения не являются окончательными и должны проверяться во время игры.

## 10. Пока не определено

- точные значения времени цикла;
- стоимость улучшения качества универсальной комнаты;
- точные формулы награды;
- влияние репутации на будущую генерацию пассажиров;
- дополнительные профессии и их особые правила;
- дополнительные типы потребления ресурсов.
