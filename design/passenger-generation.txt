# Генерация пассажиров — согласованная концепция

Документ описывает правила генерации пассажиров. Это только документация и не используется игрой.

## 1. Генерация зависит от развития порталов

При создании нового пассажира игра должна учитывать максимальную доступную вместимость портала на станции.

- При начальной вместимости 4 места обычные пассажиры, которым требуется больше 4 мест, не генерируются.
- После улучшения хотя бы одного обычного портала до 6 мест становятся доступны обычные пассажиры-гиганты, которым требуется 6 мест.
- Аналогично открываются обычные пассажиры с большими требованиями по мере развития порталов.
- Генератор не должен создавать пассажира, которого невозможно отправить при текущем развитии станции.

Для определения доступности используется максимальная вместимость хотя бы одного доступного портала, а не сумма мест всех порталов.

Пример:
- Портал №1 — 4 места
- Портал №2 — 4 места
- Портал №3 — 6 мест (улучшен)

В этом случае обычный пассажир на 6 мест может появиться, а пассажир на 7 мест — нет.

## 2. Генерация зависит от открытых точек назначения

Точки назначения определяют, какие пассажиры могут появляться на станции.

По предварительному правилу пассажир любой расы может лететь на любое открытое направление. При генерации учитываются только явно заданные ограничения особенностей, профессий/архетипов или контракта: пассажир может появиться, если у него есть хотя бы одно открытое допустимое направление. Игрок выбирает только среди открытых направлений из этого набора. Общее правило можно пересмотреть после игровых тестов.

Итоговый набор допустимых направлений рассчитывается как пересечение ограничений расы, архетипа, профессии и других характеристик пассажира с открытыми направлениями станции. Если для характеристики отдельный список не задан, она не ограничивает направления. Если после пересечения не осталось ни одного направления, такая комбинация характеристик не генерируется и не используется в контракте.

Примеры:
- Если явно заданное ограничение пассажира допускает только ещё не открытое направление, пассажир не появляется до открытия этого направления.
- Если ограничений нет, пассажир может лететь на любое открытое направление.
- Если у пассажира есть явное ограничение и открыта только часть допустимых направлений, он может появляться и лететь только в открытые направления из своего набора.
- Если у пассажира не открыто ни одного допустимого направления, он не генерируется.

Открытие новой точки назначения расширяет выбор доступных маршрутов для пассажиров и контрактов, но не добавляет уникальные механические типы контрактов. Пул пассажиров меняется только там, где ограничения для профессии, архетипа или другой особенности явно зависят от направления.

Важно: точка назначения определяет доступность пассажира для генерации, а портал определяет возможность его отправки. Это разные механики.

Архетип пассажира (например, инженер, беженец или контрабандист) — отдельная характеристика, см. `passenger-archetypes.txt`. Доступность архетипа может зависеть от открытых направлений и прогрессии станции. Необычные сочетания архетипа и состоятельности можно исключать из обычной генерации; сюжетные контракты могут задавать исключения.

## 3. Исключение для квестовых пассажиров

После принятия контракта для него создаётся отдельный портал, рассчитанный на всю требуемую группу. Очередь обычно пополняется разными пассажирами из доступного пула станции; требования активных контрактов влияют на генерацию, но не должны превращать всю очередь в поток квестовых пассажиров. Если подряд сгенерированы два пассажира, не подходящих ни под одну незакрытую потребность активных контрактов, следующий появившийся пассажир гарантированно подходит хотя бы под одну такую потребность. Считаются только фактически сгенерированные пассажиры: пока очередь заполнена и новое место не освободилось, счётчик не растёт. Гарантированный пассажир не может превышать оставшуюся потребность контрактов.

Подходящий пассажир может быть назначен на любой портал, чьим условиям он соответствует; после назначения он закрепляется только за выбранным контрактом. Это исключение не открывает соответствующие размеры для обычной генерации.

Квестовые требования должны проходить проверку совместимости до появления предложения и до генерации пассажиров. Все условия, влияющие на допуск пассажира через квестовый портал, должны быть показаны в карточке контракта: основное требование сразу, дополнительные фильтры — в раскрываемом списке. Предел состоятельности может разрешать пассажиров указанного класса и ниже, но не должен превышать максимальный класс, допустимый для заданной профессии, расы и других условий.

Генератор учитывает неудовлетворённый спрос всех активных контрактов совместно. Один доступный пассажир учитывается только один раз и может покрывать спрос лишь одного контракта, даже если соответствует нескольким. Сначала распределяются пассажиры по самым узким требованиям; генератор создаёт пассажиров, необходимых для покрытия оставшегося спроса. Это внутренний расчёт спроса, а не предварительное закрепление пассажира: до выбора игрока пассажир остаётся доступен для любого подходящего портала. После назначения он закрепляется за выбранным контрактом. Одна успешно завершённая отправка засчитывается только этому контракту. Если пассажир улетел, не будучи отправленным, он не увеличивает прогресс и его нехватка учитывается повторно.

## 4. Общий принцип

Генератор обычных пассажиров должен учитывать одновременно:
1. открытые точки назначения и доступные архетипы пассажиров;
2. максимальную вместимость доступного обычного портала;
3. другие открытые технологии и условия прогрессии.

Генерация обычных пассажиров учитывает также неудовлетворённый спрос активных контрактов. После двух подряд сгенерированных пассажиров, не подходящих ни под одну незакрытую потребность, следующий пассажир гарантированно подходит под контракт; если есть несколько незакрытых требований, выбор кандидатов при этой гарантии в первую очередь покрывает спрос с наименьшим числом доступных подходящих пассажиров. Один пассажир при расчёте спроса покрывает только один контракт.

После фильтрации недопустимых вариантов генератор выбирает пассажира по весовым вероятностям, а не с равным шансом для каждого полного сочетания характеристик. Веса должны позволять отдельно настраивать частоту рас, архетипов, размеров и состоятельности, не нарушая совместимость характеристик. Если выбранный набор характеристик недопустим или не подходит под открытые направления и вместимость порталов, он не может появиться независимо от заданного веса. Когда действует гарантия пассажира для активного контракта, выбор сначала ограничивается подходящими кандидатами; затем вес применяется внутри этого набора. Конкретные численные значения весов пока не утверждены и подлежат балансировке.

Каждый пассажир должен соответствовать доступному пулу станции и быть отправляемым с учётом текущего развития обычных порталов, кроме предусмотренных правилами квестов исключений.

## 5. Пока не определено

Для первого тестового среза контрактный генератор использует только требования по расе и максимальному классу состоятельности («бедный» или «средний класс»). Он предлагает все такие сочетания только для открытых рас и только если для условия существует хотя бы один допустимый кандидат. Профессии и архетипы не используются как фильтры контрактов до составления полной таблицы совместимости.

Следующие вопросы оставить для дальнейшего обсуждения:
- конкретный список точек назначения;
- отдельные ограничения направлений для профессий, архетипов и особенностей, если они понадобятся;
- конкретные численные веса появления рас, архетипов, размеров и состоятельности;
- точные правила расчёта требуемых мест;
- специальные/сюжетные пассажиры;
- дополнительные условия генерации.
