# 2. НЕ ДОВЕРЯЙ README

README может быть устаревшим.

Для каждой важной механики сравни:
1. документацию;
2. фактический код;
3. тесты;
4. реальное поведение.

Если они расходятся — это отдельная проблема.

Особенно ищи ситуации:
- README утверждает A, код делает B;
- тесты проверяют старую механику;
- код поддерживает старую механику, которая уже была отменена;
- новая механика частично реализована;
- документация описывает функцию, которой больше нет;
- UI показывает одно, а внутренняя модель использует другое.

# 3. ИЩИ НЕ ТОЛЬКО БАГИ

Разделяй найденное минимум на категории:

### 🔴 CRITICAL
Проблемы, которые могут сломать прохождение, создать soft-lock/hard-lock, уничтожить прогресс или привести к некорректному состоянию сохранения.

### 🟠 LOGIC
Игровая логика работает не так, как должна.

### 🟡 BALANCE
Проблемы экономики, ресурсов, наград, расходов, времени, вероятностей и темпа прогрессии.

### 🔵 UX/UI
Игрок не понимает состояние игры, доступные действия, причины блокировки или последствия действий.

### 🟣 ARCHITECTURE
Код сейчас работает, но создаёт серьёзные проблемы для дальнейшего развития.

### ⚪ POLISH
Небольшие улучшения, которые не ломают игру, но делают её лучше.

### 🟢 DESIGN OPPORTUNITY
Это не ошибка, а возможность сделать систему интереснее, понятнее или глубже.

# 4. ОСОБЕННО ИЩИ SOFT-LOCK

Это ОЧЕНЬ ВАЖНО.

Проверь: может ли игрок попасть в состояние, из которого у него больше нет ни одного реального пути к прогрессу?

Например:
- 0 кредитов;
- 0 ресурсов;
- фабрика закрыта;
- пассажир уже принят;
- пассажира нельзя отправить;
- ресурсов для содержания пассажира нет;
- заработать деньги невозможно;
- получить новый ресурс невозможно.

Ищи не только этот пример.

Проверяй систематически:
- 0 кредитов;
- 0 каждого ресурса;
- один пассажир;
- несколько пассажиров;
- нет подходящей комнаты;
- нет подходящего рейса;
- нет свободных мест;
- все комнаты заняты;
- все комнаты неправильной среды;
- фабрика закрыта;
- фабрика открыта, но без ресурсов;
- технологическое дерево частично открыто;
- игрок потратил всё;
- игрок выбрал невыгодные улучшения;
- игрок долго ничего не делал;
- игрок отказался от пассажиров;
- игрок получил редкую комбинацию характеристик;
- игрок перезагрузил игру;
- игрок продолжил старое сохранение после обновления.

Для каждого потенциального тупика отвечай: **Как игрок из этого состояния выбирается?** Если ответа нет — проблема.

# 27. ВАЖНО: НИКАКОГО «ВСЁ ХОРОШО»

Если проект действительно хорошо сделан — это нормально. Но прежде чем написать, что всё хорошо, попытайся найти контрпример.

Проводись аудит в режиме: **«Как я могу сломать эту систему?»**, а не «Как доказать, что она работает?».

---

# 28. ФИНАЛЬНАЯ ПРОВЕРКА

Перед завершением аудита задай себе:
- Есть ли soft-lock?
- Есть ли hard-lock?
- Есть ли бесконечный источник денег?
- Есть ли способ получить бесконечные ресурсы?
- Есть ли бесполезные механики?
- Есть ли доминирующая стратегия?
- Есть ли невозможные комбинации?
- Есть ли ошибки округления?
- Есть ли ошибки сохранения?
- Есть ли старый код, противоречащий новой системе?
- Есть ли UI, который врёт игроку?
- Есть ли параметры, которые не совпадают с документацией?
- Есть ли система, которую невозможно нормально расширять?
- Есть ли ранняя игра, из которой можно попасть в тупик?
- Есть ли средняя/поздняя игра, где прогресс может остановиться?
- Есть ли сценарий, когда игроку выгоднее ничего не делать?
- Есть ли случайность, способная сделать игру несправедливой?

# 29. ПОСЛЕДНЕЕ И САМОЕ ВАЖНОЕ

Не пытайся угадать, что хочет услышать пользователь.
Не защищай текущую реализацию.
Не защищай предыдущие решения.
Не соглашайся с документацией просто потому, что она существует.

**Твоя задача — найти всё, что может сделать игру хуже, сломать её, сделать её скучной, непонятной, несбалансированной или сложной для дальнейшего развития.**

Будь максимально придирчивой.

Лучше найти проблему, которую потом мы решим и сочтём неважной, чем пропустить проблему, которая через неделю окажется фундаментальной.

После аудита **не исправляй найденные проблемы автоматически**.

Сначала оставь оба документа:
- `updates/GPT6_LUNA_AUDIT_REPORT.md`
- `updates/GPT6_LUNA_TO_LEYA.md`

После этого остановись и жди дальнейших указаний.
